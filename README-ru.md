## Отказ от ответственности

> **Предупреждение**
> **Используйте на свой страх и риск!** Это **неофициальный** проект. Acer не принимала участия в его разработке. Модуль ядра был разработан методом реверс-инжиниринга официального Windows-приложения PredatorSense. Этот драйвер взаимодействует с низкоуровневыми методами WMI/ACPI, которые протестированы не на всех сериях ноутбуков. Авторы не несут ответственности за любой ущерб, причинённый вашему оборудованию.

> Все упомянутые товарные знаки, названия продуктов и логотипы (Acer, Predator, PredatorSense, Helios, Nitro, AeroBlade, CoolBoost) являются собственностью их соответствующих владельцев (Acer Inc.). Этот проект никак не связан с Acer Inc., не одобрен и не спонсируется ею.

## О проекте

Неофициальный модуль ядра Linux для подсветки RGB-клавиатуры и режима Turbo игровых ноутбуков Acer (Acer Predator, Acer Helios, Acer Nitro).

Вдохновлён и основан на проекте [acer-predator-turbo-and-rgb-keyboard-linux-module](https://github.com/JafarAkhondali/acer-predator-turbo-and-rgb-keyboard-linux-module) от [JafarAkhondali](https://github.com/JafarAkhondali) и участников. Этот проект расширяет существующий модуль ядра Linux Acer-WMI для поддержки игровых функций Acer и добавляет **полноценное desktop GUI-приложение**, разработанное на Rust и GTK4.

### Управление вентиляторами — три уровня

| Уровень | Что делает | Доступность |
|---|---|---|
| **Чтение RPM вентиляторов** | Читает скорость вентиляторов CPU/GPU (`fan1_input`, `fan2_input`) | Большинство игровых моделей (определяется автоматически) |
| **Профили вентиляторов** | Тихий / Сбалансированный / Производительность / Turbo через `platform_profile` | Модели `predator_v4` |
| **Fan PWM %** 🧪 | Управление скоростью каждого вентилятора отдельно (`pwm1`/`pwm2` 0–100%), портировано из основного драйвера `acer-wmi` через WMI — **только ядро ≥ 6.14** | Подмножество моделей с `ACER_CAP_PWM` (AN515-58, PHN16-72/73, PH16-72, …) |

> **🧪 Управление PWM вентиляторов экспериментально.** Оно портировано из драйвера `acer-wmi` основной ветки ядра Linux и использует безопасные методы WMI (без прямой записи в EC), но **не было проверено на реальном оборудовании** сопровождающим (у которого есть PH315-54, не имеющий PWM). Если у вас поддерживаемая модель, отчёты о тестировании очень приветствуются. **Используйте на свой страх и риск** — см. предупреждение в начале.

### Альтернатива: linuwu_sense (оборудование без quirk-записи, где Turbo не работает)

Резервный режим `enable_all=1` в `facer` распознаёт любую плату с поддержкой Acer WMI, но полный набор профилей `predator_v4` (5 профилей, включая `balanced-performance`/`performance`, с записываемым `turbo_state`) применяется только к платам, присутствующим в его таблице quirk-записей DMI. На плате без такой записи `platform_profile_choices` ограничен значениями `low-power quiet balanced`, а `turbo_state` остаётся доступным только для чтения, даже если прошивка поддерживает больше — об этом сообщили для устройства PHN16-73 (Macan_ARX, BIOS V1.26) в [#33](https://github.com/cleyton1986/predator-sense/issues/33).

Если это ваш случай, модуль сообщества [Linuwu-Sense](https://github.com/0x7375646F/Linuwu-Sense) (загружаемый с `predator_v4=1`) предоставляет полный набор профилей через те же общие интерфейсы `platform_profile`/`intel_pstate`/`acer-wmi-battery`, которые это приложение уже читает напрямую — без какого-либо кода, специфичного для `facer`. Начиная с `v0.2.71-preview` приложение определяет `linuwu_sense` и пропускает подсказку «установите facer», когда именно этот драйвер действительно предоставляет эти интерфейсы. RGB и калибровка термального профиля (оба доступны только через `facer`, см. выше и ниже) всё равно требуют самого `facer` и остаются недоступными под linuwu_sense.

### RGB без модуля ядра (только оборудование I2C-HID)

Некоторые модели (подтверждено: PHN16S-71, PHN16-73, AN16S-61) направляют контроллер RGB клавиатуры через отдельный чип I2C-HID (ENEK5130) вместо интерфейса WMI `facer.ko` — приложение общается с ним напрямую через `/dev/hidrawN`, поэтому это работает, даже если модуль ядра вообще не загружен:

| Функция | Статус |
|---|---|
| Статический цвет по зонам, яркость, отключение подсветки | ✅ подтверждено работает (PHN16S-71, AN16S-61) |
| Динамические эффекты — Breathing, Neon | ✅ подтверждено работает (PHN16S-71, AN16S-61) — нативно, одна запись HID, оборудование само зацикливает паттерн. На устройстве PHN16S-71 Breathing игнорирует выбранный цвет и вместо этого циклически меняет радужные цвета; на другом оборудовании может отличаться |
| Динамические эффекты — Wave, Shifting, Zoom | Только предпросмотр на экране (без записи в оборудование) — было обнаружено, что коды этих эффектов означают разное в разных поколениях оборудования, поэтому они пока не подключены |
| RGB-подсветка логотипа крышки — выкл, сплошной цвет, яркость, Breathing, Neon | ✅ подтверждено работает (PHN16-73) |

Поддержка логотипа крышки не включается по списку разрешённых названий моделей. Контроллер должен заявить целевой параметр `0x83` в своём отчёте A1 targets и вернуть соответствующие, непустые возможности A3, прежде чем интерфейс будет показан; приложение повторяет эту проверку непосредственно перед каждой записью. Демон hotkey восстанавливает только ту настройку, которую приложение ранее успешно применило после входа в систему и выхода из спящего режима, и полностью пропускает логотип, если сохранённой настройки нет или целевой параметр отсутствует.

[Независимый отчёт по AN16S-61](https://github.com/cleyton1986/predator-sense/issues/31) (см. также собственный [автономный инструмент для работы с протоколом](https://github.com/ArnarValur/Nitro16S-AI-RGB-Keyboard) от автора отчёта) выявил ещё шесть нативных проводных режимов помимо static/Breathing/Neon/Wave (аппаратный режим выключения, режим мигания при загрузке, который запускает сам EC, и ещё четыре встроенные анимации), а также цель для светодиода клавиши режима/turbo. Ничего из этого пока не подключено в приложении — для этого сначала нужен выделенный слот для нативных аппаратных кодов эффектов, поэтому это отслеживается как задача на будущее.

Тот же отчёт также включал декодированный HID report descriptor, полученный прямо с контроллера, что помогло выявить реальную ошибку: приложение читало количество зон из отчёта возможностей A3 не из того байта (`byte[3]`, фиксированной константы для класса цели), а должно было использовать байт, который для этого объявляет собственный descriptor контроллера (`byte[4]`). Исправлено в `v0.2.69-preview` как в приложении, так и в демоне hotkey. Это исправление на уровне протокола, а не изменение для конкретной модели — расположение полей report descriptor берётся из собственной прошивки чипа (один и тот же чип `0CF2:5130` на всех трёх подтверждённых моделях) — и оно не меняет ни одного байта на проводе на оборудовании, уже подтверждённом как рабочее, поскольку предыдущее значение всегда было избыточным надмножеством правильного.

### RGB на оборудовании 2024+ (Sunrex/Darfon USB HID)

Более новое поколение (PH16-72 и другие модели 2024-2026, использующие те же чипы USB HID, см. issue #26) перенесло RGB клавиатуры и логотипа крышки и с WMI, *и* с чипа ENEK5130 выше на совершенно другую пару контроллеров — Sunrex `05af:*` для клавиатуры, Darfon `0d62:*` для логотипа. Приложение определяет и управляет ими напрямую тоже, автоматически выбирая их вместо путей ENEK5130/WMI, когда они присутствуют:

| Функция | Статус |
|---|---|
| Клавиатура: Off, Static, Breathing, Wave, Snake, Neon, Spot, Star, Rainbow, 5× Slash, Zoom, Row Wave, Swiping | 🟡 реализовано, ожидает подтверждения на реальном оборудовании |
| Логотип крышки: выкл, сплошной цвет, яркость, Breathing | 🟡 реализовано, ожидает подтверждения на реальном оборудовании |

У этого чипа нет независимых зон — вся клавиатура использует один цвет/эффект одновременно, в отличие от контроллера ENEK5130 с 4 зонами выше. Проводной протокол был реверс-инжинирен побайтово из двух декомпилированных релизов официального Windows-приложения (каждая фиксированная последовательность байт и формула контрольной суммы точно совпадали между ними), а не угадан — но пока никто не подтвердил его на физическом оборудовании, поэтому считайте его непротестированным, пока не поступит реальный отчёт.

Третий чип (Chicony, Helios 300/PH317-56) использует ещё один протокол USB HID, задокументированный сообществом путём реверс-инжиниринга ([NT411/Acer-Predator-Fan-RGB-Controller-Linux](https://github.com/NT411/Acer-Predator-Fan-RGB-Controller-Linux)) и реализованный здесь на основе этой спецификации — фиксированная палитра из 7 цветов (ограничение оборудования/прошивки, а не произвольный RGB) на 12 эффектов. Тоже 🟡, ожидает подтверждения.

### Уже используете Linuwu-Sense или DAMX?

[Linuwu-Sense](https://github.com/0x7375646F/Linuwu-Sense) (и [DAMX](https://github.com/PXDiv/Div-Acer-Manager-Max), построенный на его основе) — отдельный, не связанный с этим проект, который тоже управляет оборудованием Acer Predator/Nitro на Linux. Он не является зависимостью этого проекта, и его код здесь не используется — но его модуль ядра занимает **те же GUID WMI**, которые нужны `facer`, а ядро не позволяет двум драйверам одновременно претендовать на одно и то же устройство.

Если установщик обнаруживает, что `linuwu_sense` уже загружен или установлен через DKMS, он автоматически **оставляет вашу существующую настройку без изменений** — он не добавляет `acer_wmi` в чёрный список и не принудительно загружает `facer`, поэтому не конфликтует с уже работающей установкой Linuwu-Sense/DAMX (и не ломает её). RGB клавиатуры всё равно работает через это приложение по пути HID (см. выше), независимо от того, какой платформенный драйвер активен; в этом случае управление вентиляторами/термикой остаётся за тем инструментом, который вы уже использовали для этого.

## Установка

### Готовый установщик (самый быстрый способ)

Скачайте установщик релиза напрямую и запустите его:

```console
curl --fail --location https://github.com/cleyton1986/predator-sense/releases/latest/download/predator-sense-installer --output predator-sense-installer
chmod +x predator-sense-installer
sudo ./predator-sense-installer --install
```

Установщик, привилегированный helper, слушатель hotkey и служба трея — всё это предоставляется одним и тем же multicall-бинарником на Rust. Установщик скачивает и настраивает всё без bootstrap-скрипта на shell.

### Интерактивный установщик (готовый бинарник, без необходимости в Rust toolchain)

Скачайте бинарник `predator-sense-installer` со страницы [Releases](../../releases). Это самостоятельный бинарник на Rust, а не пакет — ему всё равно нужен доступ в интернет, чтобы получить исходный код приложения (для модуля ядра) и соответствующий готовый бинарник релиза, но он полностью избавляет от установки Rust и компиляции GTK4-приложения на вашей машине:

```console
chmod +x predator-sense-installer
sudo ./predator-sense-installer
```

Выберите **опцию 1** (Полная установка). Установщик автоматически:

1. Определит ваш дистрибутив (Debian/Ubuntu/Mint, Fedora, Arch)
2. Установит системные зависимости (GTK4, libadwaita, инструменты сборки, заголовки ядра)
3. Скачает исходный код + готовый бинарник соответствующего релиза
4. Скомпилирует и загрузит модуль ядра `facer` (эта часть всегда компилируется локально — модули ядра нельзя распространять в готовом виде между разными версиями ядра)
5. Создаст пункт меню приложений со значком
6. Привяжет аппаратную клавишу PredatorSense (автозапуск при входе)
7. Настроит поддержку системного трея

Путь с готовым бинарником не требует Rust/cargo на целевой машине. Установщик также копируется в `/opt/predator-sense/` как самостоятельный инструмент управления для проверки статуса, перезагрузки модуля ядра, обновлений и удаления (см. [Опции установщика](#опции-установщика)).

После установки откройте приложение одним из способов:
- Нажав клавишу **PredatorSense** (рядом с NumLock)
- Найдя **«Predator Sense»** в меню приложений
- Запустив `/opt/predator-sense/predator-sense` в терминале

## Использование

### RGB клавиатуры

1. Перейдите в **Подсветка** на боковой панели
2. Выберите **Статический** (цвета по зонам) или **Динамический** (эффекты)
3. **Статический режим:** настройте ползунки R/G/B для каждой из 4 секций клавиатуры
4. **Динамический режим:** выберите эффект (Breathing, Neon, Wave, Shifting, Zoom) и настройте скорость
5. Нажмите **Применить**

> На оборудовании только с I2C-HID без модуля ядра (см. [Совместимость](#совместимость)), Breathing и Neon анимируются по-настоящему; Wave/Shifting/Zoom показывают только предпросмотр на экране, явно обозначенный как таковой — физическая клавиатура для них пока не меняется.

### RGB-подсветка логотипа крышки

1. Перейдите в **Подсветка** и выберите **Логотип крышки** (селектор появляется только когда обнаружена совместимая цель HID)
2. Используйте **Подсветку**, чтобы включить или выключить эмблему
3. Выберите **Static**, **Breathing** или **Neon**, затем настройте доступные элементы управления цветом, яркостью и скоростью, наблюдая за живым предпросмотром
4. Нажмите **Применить к логотипу**

Последнее успешно применённое состояние восстанавливается при запуске пользовательской службы hotkey и после выхода из режима сна/гибернации. Цвета анимированных эффектов управляются прошивкой, поэтому предпросмотр отражает их поведение, а не предлагает выбор цвета для этих режимов.

> Прошивка управляет анимацией подсветки, показываемой до того, как Linux запустит пользовательскую службу. Сохранённое состояние «выкл» восстанавливается после входа в систему, но это приложение не может подавить более раннюю анимацию BIOS/загрузки.

### Профили производительности

В системах с активным Intel P-State + HWP сторона CPU разрешается следующим образом:

| Профиль | Политика HWP | Intel EPP | Мин. производительность | Мощность GPU | Вентилятор | Сценарий использования |
|---------|------------|-----------|------------------|-----------|-----|----------|
| **Eco**⁴ | powersave | power | 5% | 25W³ | Auto | Максимальное время автономной работы |
| **Тихий** | powersave | power | 10% | 40W³ | Auto | Тихая работа |
| **Сбалансированный** | powersave | balance_performance | 17% | 80W³ | Auto | Общее использование |
| **Производительность** | powersave¹ | performance | 50% | 100W³ | Max | Игры |
| **Turbo** | performance² | 0 (принудительно ядром) | 100% | 110W³ | Max | Максимальная производительность |

Выбор любого профиля также применяет соответствующий режим вентилятора — отдельный шаг не нужен.
Выбор Производительности или Turbo переводит вентилятор в Max (как и физическая
клавиша Turbo); Тихий, Сбалансированный и Eco оставляют его в Auto.

⁴ Только от батареи, как в официальном приложении Windows: Eco никогда не предлагается
как опция при питании от сети, поэтому эта карточка появляется на странице Режимы только
когда ноутбук отключён от питания. Для этого уровня не существует подтверждённых
Acer-значений мощности/EPP, поэтому его настройки — это консервативная экстраполяция
ниже собственных значений Тихого режима, а не измеренное значение, как для остальных
четырёх.

¹ Политика HWP `powersave` у Intel P-State — это динамический алгоритм масштабирования,
а не обычный governor с минимальной частотой. Он оставляет записываемым специфичный
для модели именованный EPP, делая Производительность динамическим уровнем от 50%
до максимума.

² Сама политика HWP `performance` принудительно устанавливает EPP в 0 и ограничивает
доступный диапазон P-state его верхней границей. Predator Sense полагается на это
поведение ядра вместо того, чтобы требовать числовых записей EPP. Бэкенд определяется
по каждой политике cpufreq, без списка разрешённых моделей CPU. Другие драйверы
сохраняют существующее сопоставление `performance` + именованный `performance`, а
системы без EPP пропускают только этот опциональный элемент управления.

³ Максимально возможное через `nvidia-smi -pl`, так же как и ползунок лимита мощности
Панели GPU ниже — тихо пропускается, если `nvidia-smi` отсутствует, а на некоторых
ноутбуках vBIOS вообще не предоставляет управление лимитом мощности NVML (`nvidia-smi
-q` сообщает `Power Management Object: N/A`, любое значение `-pl` отклоняется независимо
от запрошенного). Это ограничение на уровне прошивки, а не то, что это приложение —
или любое ПО для Linux — может изменить; повышение лимита означает перепрошивку другой
vBIOS с помощью инструмента, работающего только на Windows, вроде `nvflash`, что
несёт реальный риск превратить GPU в «кирпич» и остаётся исключительно решением
владельца.

**Известное отличие от официального приложения Windows:** в режиме Тихий официальный
PredatorSense также включает Whisper Mode NVIDIA (`NvAPI_NvToppsJpacSetControl`),
которая ограничивает частоту кадров до 60 FPS, чтобы кривая вентиляторов работала
тише. Этот элемент управления — часть API драйвера NVIDIA, доступного только в
Windows, и не имеет аналога в Linux, поэтому здесь режим Тихий не такой тихий под
нагрузкой, как Тихий в Windows на том же оборудовании — это ограничение платформы,
а не ошибка этого приложения.

### Профили питания прошивки (измерено, а не угадано)

Всё в таблице выше лишь перераспределяет уже существующий бюджет мощности между
CPU и GPU. **Сам лимит мощности пакета** задаётся собственным термальным профилем
прошивки, и на некоторых моделях прошивка загружается в свой самый низкий профиль —
поэтому никакое изменение governor, EPP или `min_perf` не поднимет потолок ни на
один ватт.

`platform_profile` не всегда может достичь этих режимов. Драйвер ядра называет их
по фиксированной таблице (`BALANCED=0, QUIET=1, PERFORMANCE=2, TURBO=3, ECO=4`),
которая справедлива не для каждой прошивки. Измерено на Predator PHN16-73 (Arrow
Lake, BIOS V1.26) путём записи каждого сырого индекса и считывания лимита пакета
обратно:

| Индекс прошивки | Устойчивый (PL1) | Пиковый (PL2) | Имя через `platform_profile` |
|---:|---:|---:|---|
| 6 | 45 W | 50 W | *(нет — недостижим)* |
| 0 | 55 W | 160 W | `balanced` |
| 1 | 70 W | 160 W | `quiet` |
| 4 | 95 W | 160 W | `low-power` |
| 5 | **115 W** | 160 W | *(нет — недостижим)* |

Самый мощный и самый слабый режимы вообще не имеют имени, а три, у которых оно
есть, промаркированы в неверном порядке. Жёстко закодированная исправленная таблица
просто перенесла бы проблему на следующую прошивку, поэтому Predator Sense вместо
этого **измеряет**:

1. Модуль ядра предоставляет сырой индекс и собственную битовую маску поддерживаемых
   индексов прошивки как `/sys/devices/platform/acer-wmi/thermal_profile` и
   `thermal_profile_supported`.
2. **Режимы → Калибровка профилей** записывает каждый поддерживаемый индекс и
   считывает получившийся лимит пакета из `intel-rapl-mmio`, затем ранжирует их
   по устойчивой мощности. Занимает несколько секунд и слышимо приводит в движение
   вентиляторы во время выполнения.
3. С этого момента четыре уровня выше также управляют профилем прошивки, привязанным
   так, чтобы Тихий соответствовал реально самому слабому, а Turbo — реально самому
   мощному.

Примечания:

- **Машины без читаемого RAPL** (модели AMD, более старые Intel) не могут быть
  ранжированы. Профили всё равно перечислены и переключаются вручную, но четыре
  уровня намеренно оставляют прошивку в покое, вместо того чтобы угадывать порядок —
  на прошивке выше угадывание по индексу поставило бы Turbo на профиль 45 Вт.
- Прошивка **забывает** профиль при каждом цикле питания, поэтому служба загрузки
  повторно применяет последний выбранный вами профиль.
- На моделях, где прошивка привязывает подсветку клавиатуры к режиму питания, каждое
  переключение — включая каждый шаг калибровки — перекрашивает клавиатуру. Это делает
  прошивка, а не приложение; заново примените свои цвета со страницы Подсветка после
  этого, если это вас беспокоит.
- Физическая **клавиша переключения режима** циклически проходит тот же измеренный
  порядок; см. ниже.

### Физическая клавиша переключения режима

На некоторых моделях есть выделенная клавиша, которая циклически переключает режимы
питания. Она сообщает о себе **только** как сырой отчёт HID-ввода на встроенном
контроллере и не генерирует вообще никакого события input-подсистемы, поэтому
кажется «мёртвой» в Linux, в то время как клавиша PredatorSense (hotkey WMI) работает.

Демон отслеживает HID-устройство Acer EC для неё. Значения по умолчанию были получены
на PHN16-73 (`1025:174B`, отчёт `04 85 ff`); ожидается, что другие модели будут
отличаться, поэтому оба значения можно переопределить без пересборки:

`~/.config/predator-sense/mode_key.json`:

```json
{ "product": "0000ABCD", "report": [4, 133, 255] }
```

(строгий JSON — комментарий `//` в этом файле сделает его непарсируемым, и демон
вернётся к значениям по умолчанию с записью об этом в лог.)

Если ваша клавиша ничего не делает, демон записывает в лог каждое найденное при
запуске HID-устройство Acer (включите `debug_logging` в Настройках). Найдите нужное
с помощью `sudo hexdump -C /dev/hidrawN`, нажимая клавишу, затем укажите файл на
него — и, пожалуйста, откройте issue со значениями, чтобы они могли войти в
значения по умолчанию для вашей модели.

Прошивка также отказывается переключать режимы при заряде батареи ниже 40%; демон
сообщает об этом вместо того, чтобы клавиша выглядела сломанной.

### Автоматический профиль по источнику питания

При включении в Настройках (по умолчанию включено для новых установок), это не
просто реакция на подключение/отключение от сети — это применяется непрерывно:
- **От сети:** всегда Производительность или Turbo. Если один из этих двух уже
  активен, он остаётся без изменений — автопереключатель никогда не противоречит
  ручному выбору между ними.
- **От батареи:** всегда Сбалансированный или Тихий, никогда не Производительность/Turbo.
  Ниже 15% заряда батареи принудительно включается Тихий, независимо от
  настроенной цели.

### Панель GPU

Мониторинг GPU NVIDIA в реальном времени:
- Температура, загрузка, использование VRAM, энергопотребление (круговые датчики)
- Живые графики истории температуры и загрузки (окно 2 минуты)
- Частота ядра, частота памяти, P-State, информация о канале PCIe, версия VBIOS

### ИИ-ассистент (бета)

Опциональный локальный ИИ-ассистент на базе [Ollama](https://ollama.com), полностью
работающий на вашей машине — никуда ничего не отправляется.

1. Установите Ollama отдельно, следуя её [официальной инструкции для Linux](https://ollama.com/download/linux)
2. Перейдите в **AI** на боковой панели и загрузите модель через встроенный менеджер
   моделей (`smollm2:1.7b` или больше — модели меньшего размера ненадёжно поддерживают
   tool-calling)
3. Включите ассистента в **Настройках** и выберите **Автоприменение** (применяет
   предложения немедленно) или **Всегда подтверждать** (по умолчанию — каждое
   предложенное изменение ждёт вашего одобрения)

Ассистент читает текущее состояние оборудования (температура, вентилятор, термальный
профиль, батарея) и может предлагать или применять изменения через фиксированный,
уже проверенный набор действий — он никогда не обращается напрямую к сырому
оборудованию/EC, и каждое действие соответствует 1:1 функции, которую это приложение
уже использовало до появления функции ИИ. Модель загружается только для выполнения
анализа, затем выгружается — она не сидит бездействующей в памяти. Вся активность
ИИ записывается в постоянный, доступный для просмотра журнал действий на той же
странице.

## Устранение неполадок

<details>
<summary><b>RGB клавиатуры не меняется / застряло на одном эффекте</b></summary>

Состояние модуля ядра могло застрять. Перезагрузите его:
```console
sudo rmmod facer
sudo insmod /path/to/kernel/facer.ko
# Или используйте установщик: sudo ./predator-sense-installer → Опция 4
```
</details>

<details>
<summary><b>Модуль не загружается</b></summary>

```console
# Проверьте, существует ли устройство WMI
ls /sys/bus/wmi/devices/7A4DDFE7-5B5D-40B4-8595-4408E0CC7F56/

# Проверьте логи ядра
sudo dmesg | grep -i facer

# Убедитесь, что заголовки соответствуют вашему ядру
sudo apt install linux-headers-$(uname -r)
```
</details>

<details>
<summary><b>Клавиша PredatorSense не работает</b></summary>

```console
# Проверьте службу hotkey на Rust
systemctl --user status predator-sense-hotkey.service
pgrep -af predator-sense-hotkey

# Убедитесь, что пользователь состоит в группе 'input' (после добавления требуется
# полный выход/вход или перезагрузка)
groups | grep input
sudo usermod -aG input $USER
```
</details>

<details>
<summary><b>Страница GPU NVIDIA не показывает данные</b></summary>

```console
# Проверьте, работает ли nvidia-smi
nvidia-smi
# Если нет, установите проприетарные драйверы NVIDIA
```
</details>

<details>
<summary><b>У моей модели нет подходящей quirk-записи (отсутствуют профили/чтение вентиляторов/PWM)</b></summary>

Если вашей точной модели ещё нет в списке совместимости, попробуйте принудительно
включить все опциональные функции семейства `predator_v4` и посмотреть, что реально
работает на вашем оборудовании:

```console
sudo modprobe facer enable_all=1
# сохраняется между перезагрузками:
echo "options facer enable_all=1" | sudo tee /etc/modprobe.d/facer-options.conf
```

Это работает только через WMI (без прямой записи в EC), поэтому на оборудовании,
которое не реализует ту или иную функцию, это безопасный no-op, а не плохая запись.
Пожалуйста, [откройте issue](https://github.com/cleyton1986/predator-sense/issues)
с указанием вашей модели и того, что сработало/не сработало — именно так добавляются
новые quirk-записи.
</details>
